## 2. 프로토콜 호환성 — 기존 시스템과 충돌 지점

현재 시스템에서 이 토픽이 닿는 레이어:

```
스케일업300 (4월 착수, 목표 300억)
    ├── 연구원 프로토콜 (2026-02월 완료 예정)
    ├── 운영 생태계 확대 (20개 pool 목표)
    ├── 강사 등급체계 (프리미엄/스탠다드/비용효율)
    ├── Price Band 기반 견적 체계
    └── 이러닝 Fast-track 개발 (WIP 상한 2~3건)
```

**충돌 가능 지점:**
- A. 연구원 프로토콜이 이미 2월 중 완료 예정이었음 → 현재 상태 불명 (완료됐는지, 후속 구현이 필요한지)
- B. `Data/Databook/`의 2025 데이터가 현 분석 베이스라면, 2026 Q1 실적 반영 여부 미확인
- C. 6개 클러스터를 모두 Part1에 담으면 → 구현 3세션 이내 원칙(메모리) 위반 리스크

## 3. 설계 옵션 (최대 3개)

### 옵션 A — 수익성 구조 단일 집중 (권고)
"효율화"를 **마진 방어 관점**으로 한정:
- Price Band 체계 구축
- 활성화비 제거 및 자사상품 대체 방안
- 부가서비스 내 특강 비용 정비

**장**: 정량 측정 가능, 단기 성과 확인 용이, 스케일업300 직결  
**단**: 생태계·역할 구분 이슈는 미처리로 남음

### 옵션 B — 운영 프로세스 표준화 집중
"효율화"를 **프로토콜/메뉴얼화** 관점으로 한정:
- 연구원 프로토콜 현재 상태 확인 + 갭 보완
- 영업대표↔연구원 역할 경계 명문화
- 표준 견적서 체계 (컨플루언스 기준)

**장**: 조직 내 마찰 감소, 팀장 매니지먼트 시간 확보  
**단**: 즉각적 수익 효과 간접적

### 옵션 C — 강사 생태계 구조화 집중
"효율화"를 **공급 사이드** 관점으로 한정:
- 강사 등급체계 + 커버리지 맵 구축
- Backup 강사 2~3명 확보 원칙 실행
- 운영인턴 제도 설계

**장**: 스케일업300의 "강사/생태계 체계 수립" 직결  
**단**: 가시 성과 시차 존재, 소싱 실행은 외부 의존

## 4. 경계 조건 — 설계가 깨지는 조건

1. **"Part1" 범위 미정 상태에서 구현 착수** → 6개 클러스터 동시 처리 시 세션 내 완결 불가
2. **스케일업300과 역할 중복** → 이 토픽이 스케일업300의 실행 토픽인지, 준비 토픽인지 구분 없으면 의존 그래프 오염
3. **baseline 데이터 미확인** → `분석_2025_step2.xlsx` 내 수치 없이 "효율화" 성과 측정 불가
4. **연구원 프로토콜 현재 상태 불명** → 이미 완료됐다면 중복 설계 리스크

## 자기감사 (1차) — 현 분석 기준

**structuration**: 6개 클러스터가 동일 레벨로 나열되어 있어 우선순위 축 없음. MUST_NOW — 클러스터 간 의존 그래프 필요.

**hardcoding**: 현재 설계 단계라 코드 없음. No issue at this dimension.

**efficiency**: 옵션 3개 모두 "짓지 않음" 검토 포함됨 (옵션 간 합집합이 아닌 택1). No additional issue.

**extensibility**: Part2~N 연속 구조 가정 시 Part1 산출물이 Part2의 입력이 되어야 함. 현재 연결고리 미정. MUST_BY_N=10 — Part1 산출물 형식 정의 필요.

2차 자기감사: 발견 2개(MUST_NOW + MUST_BY_N=10). 경계조건과 겹치므로 구조적 중복 없음. 종료.
