## 2. 신규 리스크

### 🔴 R-10. G열 "26년 영업대표" 컬럼이 3종 존재 — 정책 §5 필터 기준 미정

**실측 근거:**

팀 완료 파일 (`★2026년_databook_기교1팀_260507_완료.xlsm`) 헤더 행 22의 영업대표 관련 컬럼:

| col_idx | 헤더 원본 | 정규화 후 |
|---|---|---|
| 6 | `'26년 영업대표\n(as_is)'` | `'26년 영업대표 (as_is)'` |
| 7 | `'26년 영업대표\n(현재 담당)'` | `'26년 영업대표 (현재 담당)'` |
| 8 | `'26년 영업대표\n(To_be)'` | `'26년 영업대표 (To_be)'` |

**실측 행수 결과 (팀 완료 파일 기준):**
- col_idx 6 (as_is) 기준 박정규: **117건** ← personal_stats.json 기준값과 일치
- col_idx 7 (현재 담당) 기준 박정규: **0건** (해당 컬럼 값 없음)
- col_idx 8 (To_be) 기준 박정규: **0건**

**실패 시 파손 범위:**

정책 §5는 "G열(26년 영업대표)" 필터라고만 명시. 탐지 코드가 `"영업대표"` 키워드로 최초 매칭 시 col_idx 6 (as_is) 이 맞지만, 구현자가 "현재담당자"가 의미상 맞다고 판단해 col_idx 7을 사용하면 **박정규 행 0건** 추출 → G1.a 검증 즉시 실패. "26년 담당자로 필터해야 한다"는 직관 오류가 발생할 가능성이 실재한다.

**완화 조건:**
- policy_databook_agent.md §5에 `"G열 = col 헤더 '26년 영업대표 (as_is)'"` 를 명시적으로 특정
- `header_signature.json`에 `"rep_column_key": "26년 영업대표 (as_is)"` 형태로 박제
- G1.a-2 게이트에 `"26년 영업대표 (as_is)"` 컬럼명 교차 검증 추가

### 🔴 R-11. 박정규 개인 파일은 팀 전체 스냅샷이 아닌 "본인 전담 행만" 포함 — 정책 §5 가정 붕괴

**실측 근거:**

정책 §5 (handoff §5): *"개인 파일(예: 박정규_완료.xlsm)은 팀 전체 데이터 1,052행 포함 / 영업대표 본인 행만 편집, 타인 행은 스냅샷으로 보존"*

실측:

| 파일 | 총 행수 | G열(as_is) 박정규 | G열(as_is) 타인 |
|---|---|---|---|
| 팀 완료 (`기교1팀_완료.xlsm`) | 1,054 | 117건 | 937건 |
| 박정규 개인 (`박정규_완료.xlsm`) | **1,050** | **47건** | 1,003건 |

개인 파일도 1,050행 전체를 담고 있으나, 박정규 as_is = **47건**으로, 팀 완료 파일의 117건과 일치하지 않는다.

**실패 시 파손 범위:**

P1.1 구현 목표가 "박정규 개인 파일 → G열 필터 → 117건 추출" 이라면, 개인 파일만으로는 달성 불가능. G1.a 게이트 (`CSV 행수 = 117`) 즉시 실패. 현재 설계는 **팀 완료 파일을 SOT로 G열 필터링**해야 117건이 나온다.

**원인 추정:**
- 박정규 개인 파일의 as_is 컬럼(col_idx 6)은 데이터북 기준 시점(연초) 담당자 값.
- 팀 완료 파일에서 박정규 as_is = 117건은 연초 기준 + 연중 이관 건 포함 가능성.
- 개인 파일 박정규 as_is = 47건은 현재 편집 구간만 반영된 축소 뷰일 가능성.

**완화 조건:**
- Master에 확인 필요: **P1.1의 소스 파일은 개인 파일인가, 팀 완료 파일인가?** (M5로 등록)
- 만약 개인 파일 기준이라면 117 기준값 자체가 틀렸음 → G1.a 기준값 재측정 필요
- 만약 팀 완료 파일 기준이라면 "개인 파일 정규화"라는 P1.1 명칭 자체를 수정해야 함

### 🟡 R-12. xlsm 수식 셀 — data_only=False 시 수식 문자열 반환, 매출 집계 오류 위험

**실측 근거:**

`data_only=False` (기본값) 로드 시, col 29 (26년 예상매출합계) = `'=AG23+AJ23+...'` 수식 문자열 반환.

`data_only=True` 로드 시, col 29 = `31604920` 캐시값 반환.

Arki가 R-9에서 `read_only=True` 모드를 권고했지만, `data_only` 플래그 분리는 명시하지 않았다. `read_only=True`와 `data_only=True`는 독립 파라미터다.

**실패 시 파손 범위:**

구현 코드가 `openpyxl.load_workbook(path, read_only=True)` 기본값으로 사용하면 매출 집계 컬럼 (col 29 = 예상매출합계, col 31 = 차이) 이 수식 문자열로 들어온다. 이상치 탐지 (`anomaly_thresholds.json`) 나 매출 비교 로직이 숫자 타입 가정하면 `TypeError`로 크래시 또는 무음 0 처리.

**완화 조건:**
- `normalize_personal.py` 에 `data_only=True` 명시적 지정 필수: `openpyxl.load_workbook(path, read_only=True, data_only=True, keep_vba=True)`
- Arki 자기감사 MUST_NOW 목록에 추가 권고

## 3. 가정 감사

**A-1. "개인 파일은 팀 전체 스냅샷"이라는 가정**
- 출처: 정책 §5, handoff §3.2
- 실측에서 R-11로 반증됨
- 검증 방법: `personal_stats.json`의 `total_rows=1052` vs 개인 파일 실측 행수 비교 → 1050으로 이미 불일치 (2행 차이 존재)

**A-2. "G열 필터 기준 컬럼은 자명하다"는 가정**
- 출처: 정책 §5 "G열(26년 영업대표) 기준 필터"
- 실측에서 동일 행에 `as_is` / `현재 담당` / `To_be` 세 컬럼이 공존
- 검증 방법: `header_signature.json`에 필터 대상 컬럼 full name 명시 후, 코드에서 exact match 탐지

**A-3. "박정규 117건은 팀 완료 파일 기준으로 확정됐다"는 가정**
- 출처: `personal_stats.json` — 파일명에 "personal"이 포함되어 있어 개인 파일 기반 통계인지 팀 완료 파일 기반인지 불명확
- 실측: 팀 완료 파일의 G열(as_is) 박정규 = 117건, 개인 파일 = 47건
- 검증 방법: `personal_stats.json`의 출처 파일 명시 (`source_file` 필드 추가 권고)

**A-4. "수식 셀은 openpyxl read_only=True 모드에서 안전하게 읽힌다"는 가정**
- Arki 자기감사에서 `read_only=True` 권고했지만 `data_only` 처리는 언급 없음
- 실측: read_only=True 기본값은 `data_only=False`와 동일 → 수식 문자열 반환
- 검증 방법: `data_only=True` 지정 후 col 29 타입 확인 (`isinstance(v, (int, float))`)

**A-5. "G1.a 검증 기준값 117은 이미 확정됐다"는 가정**
- Arki 게이트: `G1.a 통과 기준 = 박정규 추출 행수 = 117`
- 실측: 어느 파일·어느 컬럼 기준인지에 따라 47~117 사이 변동
- 검증 방법: R-11 해소 후 기준값 재측정 + `personal_stats.json`에 source_file 명시
