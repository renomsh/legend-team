# Ace — Debate Round 1: 매트릭스 필요 여부 + 설계 기준

## 1. Arki 5종 vs Ace 2축 4패턴 — 충돌 아닌 레이어 분리, 단 2축이 자동 판단에 적합하다

두 구조는 경쟁하지 않는다. **레이어가 다르다.**

Arki의 5종(strategy/structure/risk-audit/cost-eval/explore)은 **역할 기여 유형**을 분류한다. "이 토픽에서 어떤 종류의 역할 기여가 필요한가"를 기술한다.

Ace의 2축(closed/open × decision/execution)은 **토픽 입력 시점에 Nexus가 판단 가능한 속성**을 기준으로 한다. Master의 발화를 받는 순간 Nexus가 판단할 수 있는 2개 축이다.

Jobs가 정확히 지적했다: Arki의 5종은 토픽 성격이 먼저 정해져야 분류 가능한데, 분류 결과를 기준으로 사용한다. **순환이다.** "risk-audit 유형"이라는 사실은 Riki를 불렀더니 Riki가 나왔다는 것과 다름없다. 입력 기준이 아니라 출력 기술이다.

그렇다면 공존 구조는 이렇다:
- **2축** = Nexus 자동 판단 기준 (입력 레이어)
- **5종 subjectType** = 사후 기록용 레이블, 또는 매트릭스 결과 태그 (출력 레이어)

Arki 5종을 판단 기준으로 사용하면 Nexus는 "이 토픽은 risk-audit인가?"를 판단하기 위해 이미 Riki를 부른 결과를 미리 알아야 한다 — 불가능하다. 2축으로 판단하면 "이 토픽은 전제가 닫혀 있고 결과물은 결정이다"를 발화 시점에 판단할 수 있다.

**결론**: 자동 판단 기준은 2축 유지. Arki 5종은 세션 로그 레이블로 활용 가능하지만 dispatch 기준에서 제외.

## 2. Nova의 "역할 = lens vs stage 불일치" — 설계에 실질 영향 없다

Nova의 비판은 이론적으로 옳지만 실천적으로 허구다.

"역할이 stage로 운영되면 lens 특성을 훼손한다"는 주장의 전제는: *발언 순서가 발언 내용을 왜곡한다*는 것이다.

그런데 역할의 lens는 발언 순서에 의해 결정되지 않는다. Riki는 어떤 순서에 있든 실패 모드를 발굴한다. Arki가 먼저 설계를 놓으면 Riki는 그 설계의 결함을 감사한다 — 이것이 "stage 오염"인가? 아니다. Arki 발언을 인풋으로 받아 자신의 lens를 발동하는 것이다. **lens의 독립성은 순서와 무관하다.**

Nova가 정확히 지적한 것은 "Arki 선두 고정"의 문제다. 이건 lens/stage 불일치가 아니라 **매트릭스 설계에서 첫 발언자를 상황에 따라 달리 해야 한다**는 주장이다. 이는 2축 매트릭스가 이미 해결한다 — open 토픽은 Jobs/Ace 선두, closed 토픽은 Arki 선두.

**결론**: Nova의 lens/stage 비판은 2축 매트릭스 설계의 타당성에 영향을 주지 않는다. 첫 발언자 유연화가 해결책이고, 그것이 2축의 목적이다.

## 3. Jobs의 "매트릭스 = 또 다른 고정 테이블" 위험 — 형식 문제이지 구조 문제가 아니다

Jobs의 반박 핵심: "원칙 3줄이면 충분하다, 매트릭스는 사족이다."

동의한다 — **완전성 착각을 유발하는 표 형식의 위험에 대해서는.** 그런데 이것은 형식 선택의 문제이지, "판정 기준을 4패턴으로 외재화한다"는 내용의 문제가 아니다.

Jobs가 제안한 "원칙 3줄 + 예시 4건"은 내가 제안한 2축 4패턴과 **논리 구조상 동일하다.** 차이는 시각화 형태뿐이다. Jobs가 "표로 만들지 말자"고 하는 것을 수용한다 — 나도 표보다 원칙 + 예시 형태가 완전성 착각을 덜 유발한다는 데 동의한다.

그러나 Jobs가 "만들지 말아야 한다면 대안이 없다"고 스스로 인정했다. 만들어야 한다. 형식을 표가 아닌 원칙+예시로 하는 것에 동의한다. 내용은 그대로다.

**수정**: "2축 매트릭스"라는 명칭을 "판정 원칙 + 4패턴 예시"로 표기 변경. 내용(2축 × 4패턴)은 유지.

## 4. Riki의 게이트 요구 — 확인 질문 트리거 조건을 구체화한다

Riki가 제기한 R-1(분류 오판 단일 실패점)은 실재 위험이다. 매트릭스가 있든 없든 Nexus 분류 오판은 발생한다. 문제는 오판 발생 시 어떻게 잡느냐다.

**트리거 조건을 다음과 같이 구체화한다:**

Nexus가 Master에게 1문장 확인 질문을 트리거하는 조건:

| 신호 | 설명 | 예시 |
|---|---|---|
| **축 1 불확실** | closed/open 판단이 50/50인 경우 — 목표가 발화에 명시되지 않음 | "API 좀 바꿔" (범위 불명) |
| **축 2 불확실** | decision/execution 경계가 불명확 | "인증 관련해서 정리해" |
| **Grade 상향 신호** | D 키워드 없는데 파일·시스템 범위 언급 있음 | "전체 설정 체계를 바꿔" |
| **기본 상향 안전장치** | 위 셋 중 1개라도 해당하면 A로 올리고 1문장 확인 |  |

Riki가 요구한 "불확실 버킷" = 위 테이블의 "기본 상향 안전장치"다. 불확실하면 A로 올린다. 하향 오분류가 치명적이므로 비대칭 설계가 맞다. Jobs도 동일하게 인정했다.

"게이트 유지"는 tool blocker가 아니라 **1회 확인 질문**으로 구현한다. Nexus가 "이 토픽은 [판정 결과] 방향으로 진행합니다 — 맞으면 그냥 두세요"라고 먼저 선언하는 방식이다. 묵인 = 진행. 수정 = 수정 후 진행.

## 5. Ace 최종 판정 — 단일 최적해

**채택: 2축 원칙 (표 형식 아닌 원칙+예시로 표현)**

- 내용: 불확실성(closed/open) × 결과물 유형(decision/execution) 2축, 4패턴 예시
- 형식: Jobs 제안대로 "판정 원칙 3줄 + 대표 예시 4건" — 표의 완전성 착각 제거
- 미매칭 처리: Nexus 상향 안전장치 (불확실 → A 기본값) + 선언-묵인 1회 확인

**폐기: Arki 5종 subjectType (dispatch 기준으로서)**
- 출력 레이블로는 활용 가능, 입력 판단 기준으로는 순환이라 불가

**폐기: Nova 역할 자기선언 대안**
- 조율 비용이 현재보다 높고, Nexus 판단력 퇴화 위험을 해결하지 못함

**C/D 통합 입장 유지** (blind-parallel 발언 D1과 동일):
- Riki R-2의 "구조 결함 누적" 위험은 실재하나, 완화 조건이 내 D1 발언과 일치한다 — "구조 검토 필요 시 B로 격상" 판단을 Nexus에 위임하는 것이 C를 문서상 유지하는 것보다 실효적이다
- 단, Riki가 제안한 "2개 이상 기존 파일 수정 시 Arki 자동 호출" 조건을 D 정의에 인라인으로 박아 격상 트리거를 명시하는 것을 수용한다
