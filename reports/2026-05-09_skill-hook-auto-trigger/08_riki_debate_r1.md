# Riki — Phase 4 debate r1 (plugin recommend 실패모드)

## §1 실패모드 5건

| ID | 시나리오 | 영향 | 확률 | mitigation + fallback |
|---|---|---|---|---|
| 🔴 R-1 | **추천 노이즈 누적** — 매 UserPromptSubmit "추천 plugin: X,Y,Z". 250 turns 누적 시 컨텍스트 5~10% 점유 | 출력 오염, 본 응답 결론 희석 | 高 (구현 그대로면 100%) | 추천 출력은 채팅 stream 아닌 sidecar(파일·UI). fallback: 매 prompt X, 키워드 hit 시만 |
| 🔴 R-2 | **false recommend (D2 직격)** — plugin description 거짓·과장 시 잘못 추천. 예: `mcp__computer-use__*`이 "텍스트 분석"으로 자칭하면 무관 토픽에 추천 | 신뢰 추락 1회로 시스템 폐기 압력 | 中 (150+ 중 부정확 ≥1건 거의 확실) | description+sandbox 검증 후 화이트리스트만. fallback: 미검증은 "검증 안 됨" 라벨 |
| 🟡 R-3 | **plugin 부재 시 추천** — 미설치 skill 추천 → 클릭 시 에러 | 무의미 추천 → 신뢰 저하 | 中 | available-skills 교차 확인. fallback: "설치 필요" 표시 |
| 🟡 R-4 | **skill 충돌·우선순위 모호** — 동일 키워드("데이터")에 5개 매칭 시 어느 1순위? | 1순위 오판 = R-2와 동일 | 高 (150+ 규모면 빈발) | priority 테이블 + Master override 기록. fallback: 충돌 시 추천 X, 선택지만 |
| 🔴 R-5 | **추천만 누적·적용 0 패턴 학습** — Master 추천 3~5회 무시 → "노이즈" 분류 → 기존 미사용 문제 그대로 + 추천 인프라 매몰비용까지 | 핵심 목표 실패 + 복잡도만 증가 | 高 | 추천 클릭률 KPI 박제 (4주 누적 클릭률 <10% → 자동 폐기). fallback: ROI 임계 미달 시 즉시 롤백 |

## §2 메모리 feedback 충돌 검증

| 메모리 | 충돌 | 근거 |
|---|---|---|
| 정착된 정책 재질문 금지 | 충돌 가능 | 매 prompt 추천 = 매번 묻는 형태. → "선언형 옵션 제시"로 한정 |
| 결정 불요 자동 진행 | 충돌 가능 | 추천 후 Master 선택 대기 = 게이트. → 무응답=무적용, 명시 클릭 시만 |
| 측정 위한 측정 금지 | 충돌 高 | 추천 정확도·클릭률·만족도 측정 인프라 과투자 위험. → KPI 1개(클릭률)만 |
| 동일 역할 다회 호출 자동 감시 금지 | 낮음 | 단, 거부 패턴 자동 추적 시 감시 패턴화 위험 → 추적 X |
| 실무용 병기 vs 아트 — 과투자 금지 | 충돌 高 | 메타 인프라. ROI<0이면 즉시 폐기 조항 필수 |

## §3 거부 논리

1. 매 프롬프트 추천 채팅 출력 (노이즈 누적, 정책 위반)
2. plugin description 신뢰 후 추천 (D2 위반, sandbox 검증 없으면 금지)
3. 자동 1순위 적용 (Master 선택 게이트 없이) — 1순위 오판 1회로 신뢰 추락
4. 150+ 전체 한 번에 매칭 — 성능·정확도 저하
